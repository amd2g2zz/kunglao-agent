## 门 A（P1）：接线完整性——GitNexus 全面扫描，零装饰面

### 方法（GitNexus + 交叉 grep，四类断线检测）

按 GitNexus 纪律（主仓根运行、`--repo` 指定、索引先 `node .gitnexus/run.cjs analyze` 刷新到当前 HEAD）：

1. **零调用者扫描**：GitNexus 列出 `scripts/rlvr/*.py` 与 `hooks/*.py` 全部导出符号的调用图入度；入度=0 且非 CLI（无 argparse/__main__）且非 settings 路径引用 = 候选装饰面。交叉 grep（import/by-name 字符串，覆盖按名派遣）复核。
2. **EMIT 词表双向核对**：EMIT_ACTIONS ~150 词 × 生产 emit 位点（正向孤儿=注册未发射；反向未注册=发射未注册）。已有 emit_gate 双向门——在当前 HEAD 重跑并出清单。
3. **账本读写对账**：`runs/` 69 路径逐一标注 writer/reader；**只写不读**（写完没人消费=决策盲账）与**只读不写**（读一个不存在的源=僵尸消费）分别列出。
4. **拒绝面可达性**：每个 REJECT 码（snapshot/devreason/methodfamily/tiercons/plan/granularity/zerooutput/ladder/sampler-exit 等）构造一次触达测试（合成 payload 走真 hook），拒绝码不可达 = 面已死。

### 产出与判据

- 产出：`docs/architecture/wiring-census.md`（四类清单 × 每项处置：接线 / 退役[owner 签核] / 基线豁免）。
- 完成判据：**零候选装饰面遗留**（全部接线或签核退役）；五活体指纹在合成活体夹具上全部可证。

## 门 B（P2）：真实学习——回路必须产出一次可测量的真实学习

### 设计

**家族簇战役**：从语料选一个同族簇（建议 mod-crypto 族：`mod-crypto-l1` + 2-3 个同族变体），每单位完整跑一轮（init 武装 → 派遣 → 结算 → 后验更新），N=3-5 单位 × 每单位 3-8 次派遣，`store_mode: per-arm`（同臂内跨单位累积——这正是学习发生的地方）。

### 度量（全部账本机械可测）

| 度量 | 定义 | 判据 |
|---|---|---|
| 后验位移 | 相邻派遣间 Beta 均值向量的 L1 变化 | ≥1 次 >0.05 的显著位移（后验真的动了） |
| 倾向轨迹 | 每次派遣的 sampled_family propensity 序列 | 出现非均匀收敛（某家族倾向持续上升且与信用正相关） |
| 复读改善 | 同族第 k 个单位的 time-to-PASS / 派遣数 vs 第 1 个 | 斜率为负（后做的更快）——**学习转移的直接证据** |
| 信用非退化 | 信用序列 distinct 值 ≥2 且 std > 0 | 全 1.0 或全 0.0 = 信号死（触发门 C 处置） |

### 完成判据

四指标中 **后验位移 + 复读改善** 必须同时成立（"真实完整的学习"=状态变了且行为变了）；只满足其一记 PARTIAL，进入门 C 诊断（信号问题还是更新问题）。

### 预算

5 单位 × $2-4 ≈ **$10-20**（loop 单价按 rc2 实测上限估）。

## 门 C（P3）：学习信号评估与控制

### 信号质量四指标（在门 B 的账本上离线计算）

1. **覆盖率**：产生结算信用的派遣 / 总派遣 ≥ 90%（不足=武装覆盖或结算链有洞）。
2. **非退化性**：信用序列 distinct ≥2 且 std ≥ 0.15（全常数 = 无信息）。
3. **正确性相关**：信用与独立 oracle 判定的一致率 ≥ 80%（信用高但 oracle 错 = 信号在撒谎）。
4. **噪声隔离**：outcome_class=infra 行确认不入 warm pools（已实现，验证面）。

### 控制机制（落地三件）

1. **武装覆盖率门**：init 后 oracle/cases 空 → 分析入口拒绝（W1 已落，验证面）。
2. **退化熔断**：连续 5 次结算信用同值 → 熔断学习更新（后验冻结）+ blocker 事件（不许在死信号上继续"学习"）。
3. **信号契约文档**：`docs/architecture/rl-signal-contract.md`——奖励定义、边界、排除类、退化判据，作为后续一切 RL 变更的引用基准。

### 完成判据

四指标全过 + 熔断机制在合成退化序列上验证触发 + 契约文档评审通过。

## 门 D（终局实验）：三臂对照——价值证明或证伪

### 设计（沿用 #694 预注册骨架，按本计划修正单位集）

- **单位**：六单位家族簇（门 B 同簇扩到 6 单位；同族有学习转移空间，这正是 RL 的目标场景）。
- **臂**：
  - **H0** 裸 Claude Code（同预算/同 wall cap/同 checker）；
  - **H1** 全 harness、RL 决策关闭（家族均匀/无倾向/无准入——把 #773 W2 采样改为记录式、W3 receipt 关闭）；
  - **H2** 全 harness + RL 决策（采样出口/准入/后验更新全开）。
- **轮次**：每臂顺序跑全部 6 单位 1 轮（`store_mode: per-arm`，臂内跨单位累积=学习发生处）；若结果需要显著性，第二轮回补（预注册：最多 3 轮，固定 N 不偷看）。
- **隔离**：臂间不共享 store（结构保证）；H1 与 H2 同一 slim 快照（谁决定的唯一差异）。

### 度量与判据（预注册，跑前锁定）

| 维度 | 成功判据（RL 价值证明） | 证伪判据（止损） |
|---|---|---|
| 成功率 | H2 ≥ H1 ≥ H0 | H2 ≤ H0 |
| time-to-PASS（中位） | H2 斜率为负（后单位更快）且中位 ≤ H0 | 无斜率且 ≥ H0 |
| 成本 | H2 ≤ H0 × 1.5（准确性换取上限） | H2 > H0 × 1.5 且成功率无优势 |
| 学习轨迹 | H2 臂内后验位移>0 且倾向收敛（门 B 复证） | 全程无位移 |

- **价值证明成立**：成功率判据 + （time 或 cost 至少一维）同时成立，且学习轨迹成立 → RL 层保留并加大投入。
- **证伪成立**：H2 相对 H0 无任一维优势，或学习轨迹死亡 → **退役 RL 层**（owner 2026-10-18 已预签此止损方向），harness 保留，编排简化为 pi 式循环 + 本套验证纪律。
- 边界情形（如成功率平、成本高但斜率为负）：报告如实数据，owner 终裁。

### 预算

6 单位 × 3 臂 × $2-4/单位（H0/H1）与 $4-8/单位（H2 loop）≈ **$70-120**；二轮回补再 +$70-120（预注册上限）。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| GitNexus 索引过期漏检 | 先 analyze 刷新再扫；交叉 grep 复核（双源） |
| 门 B 语料不足以触发学习 | 选同族最近邻簇；单位数可扩（预算线性） |
| H1/H2 快照实现引入新偏差 | 快照 diff 审查+lockstep 测试（只差"谁决策"） |
| runner 网络抖动（rc2 期间实测） | 断点 harvest 已内建；失败单位重跑计入固定 N |
| 负结果 | 就是结果：按止损线退役，harness 保留——本计划对负结果同样交付价值（省掉无限维护） |

## 7. 本计划不做的事

- 不做训练/微调（RLVR 是账本反馈+上下文策略，无梯度）。
- 不新增奖励数学（Beta/DTS 内核不动；本计划只喂它和测它）。
- 不以 token 节省为主要 KPI（owner 裁决：先能力增益，token 是副产品）。

# 案例 2：Web 请求签名还原

> 单页脱敏实战报告。目标为在线商业产品；披露刻意最小化 —— 不公开任何
> 还原出的密钥、参数取值或协议字段值。

## 目标

一个大规模 Web 应用的请求签名方案：API 请求上附带签名参数是如何算出来的。
任务：刻画签名计算的完整逻辑，并对其全部记录在案的交互离线复现 ——
包括未向分析过程披露的扣留交互。

## 防御面

- 打包混淆的 JavaScript bundle
- bundle 内的反调试陷阱与诱饵代码路径
- 混入签名输入的运行时生成 nonce 材料
- 客户端主动的反爬虫指纹检测

## Agent 路线

1. Bundle 解包与去混淆；为解包后的代码建索引以便导航。
2. 沿调用图静态追踪签名入口。
3. 在反检测浏览器中做动态插桩：hook 与网络抓包记录在线
   （输入 → 签名）交互。
4. 从诱饵路径中剥离承重计算；定位 nonce 材料进入签名输入的位置。
5. 离线重实现签名计算。
6. 对记录语料做重放验证；扣留交互直到最终检查前始终不进入分析视野。

## 判决

签名方案被端到端刻画，计算对全部记录交互逐字节复现一致 ——
含扣留交互。

## 证明点

Web 车道能力：在混淆与反爬防护下完整刻画生产级签名方案；扣留重放
让结论保持诚实 —— 复现无法过拟合从未见过的交互。

# 案例 1：Android 加固 native crackme

> 单页脱敏实战报告。该目标为本项目自建的结构化 crackme，用于演练完整防护栈，
> 因此其还原出的常量可以公开。

## 目标

一个商业级强度的 Android 加固 crackme：Rust 编写的 native 库（`.so`），
内含 license 校验例程。任务：穿透防护栈还原其中埋藏的三个密码学参数，
并离线重实现该推导 —— 对每一组抓到的输入/输出对逐字节复现，
验证时不依赖设备、不依赖 App。

## 防御面

- 校验派发器上的控制流平坦化（CFF）
- 自修改代码（运行时解密自身代码体的 stub）
- 反 hook、反模拟、反 dump 检测
- 常量静态加密，只在例程内部物化
- 一条产出"貌似合理实则错误"结果的诱饵计算车道

## Agent 路线

1. `.so` 静态分诊：ELF 结构、去符号处理、节区与导入扫描。
2. 对平坦化派发器做控制流恢复，把校验例程从加壳脚手架中剥离。
3. 定位自修改 stub 与常量解密路径；不执行样本，推导出解密后的代码体。
4. 诱饵判别：对两条计算车道做字节级发散探针，直到真推导与诱饵可分离。
5. 还原三个参数 —— ChaCha-KDF 的 sigma 字、AES 形制的 S-box 种子、
   16 字节 license magic。
6. 用还原出的材料离线重实现推导。
7. 重放验证：对全部抓包对复现，**含诱饵车道上抓到的对** —— 它们必须
   作为错误答案基线被正确复现，而不是被误当成真车道。
8. 全程无人值守；运行中的 worker 死亡被循环检测到，其 claim 自动重新
   入队，无需人工介入。

## 判决

官方 checker 判定通过：**常量 3/3 还原，重放 18/18 逐字节一致** ——
18 组中包含诱饵路径输出，被正确评分为"如实复现的诱饵"而非真车道。

## 证明点

在重防护 native 目标上的无人值守多小时深度、加密常量与自修改代码下的
诱饵判别、以及由机械 oracle（而非自我评价）强制收敛的逐字节一致。

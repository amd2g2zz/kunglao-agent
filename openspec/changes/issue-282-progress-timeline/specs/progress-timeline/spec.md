# Spec Delta — progress timeline (issue #282)

## ADDED Requirements

### Requirement: progress.txt SHALL be a rendered, ledger-derived timeline

progress.txt MUST be generated by `scripts/progress_timeline.py` from the
kunglao_log event ledger (`runs/logs/kunglao-*.jsonl`), with every ledger
event rendered as exactly one `E` row in tick order (tick = the #255 epoch
axis; a documented-unreadable tick renders as `tick=?`, never a fabricated
value) and worker narrative entries interleaved as `N` rows at their
timestamps. The ledger remains the source of truth; progress.txt is the
complete human-scannable VIEW and is NOT machine-ingested state (the #530
disposition holds: state_anchor and external_kicker continue to never read
it).

#### Scenario: a case with machine events and worker entries renders gap-free

- **WHEN** a workspace ledger carries N machine events and M narrative
  entries exist (sidecar or worker appends), and the renderer runs
- **THEN** the rendered progress.txt contains exactly N `E` rows (one per
  ledger event, present with its actor/action/ts) whose tick values are
  non-decreasing, and the M narrative texts appear as `N` rows interleaved
  between their surrounding event timestamps

#### Scenario: re-render is byte-identical for the same inputs

- **WHEN** the renderer runs twice over an unchanged ledger and sidecar
- **THEN** the two outputs are byte-identical, and the second
  render-and-repair performs no write (the file mtime is preserved)

#### Scenario: a deleted line is repaired by the next render

- **WHEN** any line is deleted from a previously rendered progress.txt and
  the renderer runs again over the unchanged ledger and sidecar
- **THEN** the file is restored byte-identically (self-healing by
  construction)

### Requirement: narrative entries SHALL be preserved across re-renders

Worker narrative lines appended to progress.txt MUST survive every
re-render byte-verbatim (existing append protocol,
`agents/kunglao-worker.md` step 4, unchanged). The renderer MUST ingest
narrative lines into the durable sidecar `runs/progress-narrative.jsonl`
(dedup by exact text) before the file is rewritten. Pre-#282 legacy
content MUST migrate the same way on the first render.

#### Scenario: worker appends between rounds survive the next render

- **WHEN** a worker appends `[YYYY-MM-DD HH:MM] [W-3 DONE] summary` to
  progress.txt after the last render, and the next checkpoint render runs
- **THEN** the line appears verbatim as an `N` row in the rendered
  timeline, is stored in `runs/progress-narrative.jsonl`, and is not
  duplicated by subsequent renders

#### Scenario: legacy pre-render content migrates losslessly

- **WHEN** a workspace's progress.txt contains pre-#282 free-form content
  and the first render runs
- **THEN** every non-empty legacy line appears verbatim as `N` rows and no
  line is dropped

### Requirement: the renderer SHALL render at checkpoint and resume faces

The renderer MUST run at the convergence checkpoint — immediately after
`convergence_check.main()` appends the state snapshot (the tick writer) —
and at resume, where `kunglao_resume.main()` MUST render before building
the recovery brief (render-then-read). Both faces are fail-open: a render
failure never blocks the convergence decision or the resume brief.

#### Scenario: a convergence round refreshes the timeline in lockstep

- **WHEN** `convergence_check.main()` completes a decision and appends its
  snapshot to the convergence ledger
- **THEN** the renderer runs afterwards, so the timeline includes that
  round's events and the new tick

#### Scenario: resume reads a current timeline

- **WHEN** `kunglao_resume.main()` runs on a crashed workspace whose
  progress.txt is behind the ledger
- **THEN** the on-disk progress.txt is repaired to the current rendered
  form before the brief is built, and the brief's progress row reports the
  render state

### Requirement: resume SHALL stay state-read-only except the derived view

Resume MUST NOT write any file except the two sanctioned issue-282 faces:
the derived progress.txt timeline view and its
`runs/progress-narrative.jsonl` narrative mirror (the #466 read-only
contract, amended and documented in
`openspec/changes/issue-282-progress-timeline/design.md`). Resume MUST
perform both writes only when the rendered content differs from the
on-disk content. The ledger, state files, and every other artifact MUST
remain untouched, and `build_brief` MUST remain pure-read.

#### Scenario: resume repairs only the timeline view

- **WHEN** resume runs on a workspace with a stale progress.txt
- **THEN** every file except progress.txt and its
  `runs/progress-narrative.jsonl` narrative mirror is byte- and
  mtime-identical to the pre-resume snapshot, and the ledger line count is
  unchanged

#### Scenario: steady-state resume touches nothing

- **WHEN** resume runs twice with no new events between the runs
- **THEN** the second run performs no write at all (progress.txt mtime
  preserved)

### Requirement: an unreadable ledger SHALL never destroy the timeline

When the event ledger cannot be read, the renderer MUST NOT write
progress.txt: an existing human file stays untouched (worker narrative
preserved), the skip reason is returned to the caller, and the resume
brief's progress row carries the annotation.

#### Scenario: directory at the ledger path leaves the file untouched

- **WHEN** `runs/logs/kunglao-<date>.jsonl` cannot be read (e.g. a
  directory at the path) and a rendered progress.txt exists
- **THEN** the renderer performs no write, the existing file content is
  unchanged, and the returned status carries the unreadable-ledger reason

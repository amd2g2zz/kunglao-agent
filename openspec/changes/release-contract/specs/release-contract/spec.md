## ADDED Requirements

### Requirement: the repo SHALL own a versioned dependency manifest and lockfile

The repository root SHALL contain `pyproject.toml` (declaring `name`,
`version`, `requires-python >= 3.11`, and `dependencies` = the third-party
modules actually imported by `scripts/`, `hooks/`, `tools/`, `tests/`,
`memory/scripts/`: `PyYAML`, `pefile`, `capstone`, `jsonschema`; plus a `dev`
extra containing `pytest`) and `uv.lock` (generated by `uv lock`). A fresh
clone SHALL be installable with `uv sync --locked` without any hidden local
state. The manifest's `version` SHALL equal the `[project].version` in
`pyproject.toml`.

#### Scenario: fresh clone installs with the documented command
- **GIVEN** a fresh clone at this revision with `pyproject.toml` and `uv.lock` present
- **WHEN** `uv sync --locked` is run
- **THEN** the command exits 0 and creates a `.venv` containing the declared dependencies

#### Scenario: version agreement between manifest and pyproject
- **GIVEN** `release-manifest.yaml` with `version: "1.9.29"` and `pyproject.toml` with `version = "1.9.29"`
- **WHEN** `scripts/release_receipt.py --check` is run
- **THEN** validation passes (no version-mismatch error)

### Requirement: agent assets SHALL be repository-owned

The repository SHALL contain `agents/` with the documented agent definitions
(`kunglao-worker.md`, `kunglao-redteam.md`, `ghidra-light.md`, `floss-filter.md`,
`pefile-signature.md`, `cti-correlator.md`, `go-symbols.md`, `shodan-host.md`,
`verdict-scorer.md`, `verdict-redteam.md`), and `release-manifest.yaml` SHALL
declare every one of them. A receipt generated from the tree SHALL record each
asset's path and sha256 digest.

#### Scenario: declared agent asset exists
- **GIVEN** `release-manifest.yaml` declaring `agents/kunglao-worker.md`
- **WHEN** `scripts/release_receipt.py --check` is run
- **THEN** validation passes and the receipt's `assets.agents` contains the entry with a non-empty `sha256`

#### Scenario: undeclared-but-missing asset fails validation
- **GIVEN** a manifest overriding the path to a nonexistent file (`--manifest` pointing at a manifest declaring `agents/does-not-exist.md`)
- **WHEN** `scripts/release_receipt.py --check --manifest <override>` is run
- **THEN** the script exits 1 and reports the missing asset

### Requirement: the documented CLI surface SHALL be real and receipt-validated

`scripts/kunglao.py` SHALL register the five documented router subcommands
`decide`, `tick`, `verify`, `record`, `health` (the latter two as thin
delegation to `kunglao_verify.main` / `kunglao_record.main`). The eight
independent CLIs (`kunglao.py`, `kunglao-decide.py`, `kunglao-verify.py`,
`kunglao-record.py`, `kunglao-monitor.py`, `kunglao-init.py`, `kunglao-eval.py`,
`kunglao-digest.py`) SHALL remain executable with `--help` exit 0, and
`release-manifest.yaml` SHALL declare all of them plus the router subcommands.

#### Scenario: all eight CLIs answer --help
- **GIVEN** the repository tree
- **WHEN** each of the eight CLIs is invoked with `--help`
- **THEN** each exits 0

#### Scenario: router exposes the documented subcommands
- **GIVEN** the repository tree
- **WHEN** `python scripts/kunglao.py verify --help` and `python scripts/kunglao.py record --help` are invoked
- **THEN** both exit 0 (previously `invalid choice` errors)

### Requirement: a machine-readable release receipt SHALL be producible locally and in CI

`scripts/release_receipt.py` SHALL produce a JSON receipt conforming to
`schemas/release-receipt.json` containing: `schema_version`, `revision`,
`generated_at`, `dependencies` (pyproject + uv.lock paths and sha256),
`assets` (agents/hooks/templates/openspec_changes paths and sha256), `clis`
(name + `help_exit`), `router` (command, subcommands, `help_exit`), `tests`
(command, collected/passed/failed/skipped), and `valid`. Test results SHALL be
read from a junit XML file given via `--pytest-junit`, or by running the
standard test command (`python -m pytest -q`) when none is given. The receipt
SHALL NOT contain secrets — inventory digests only. Exit code SHALL be 0 when
the receipt is written and validation passes, 1 otherwise. `--check` SHALL
validate without writing a receipt; `--manifest <path>` SHALL override the
manifest location; `--out -` SHALL write to stdout.

#### Scenario: receipt generation from junit result
- **GIVEN** a junit XML recording `tests=625 failures=6 skipped=1`
- **WHEN** `scripts/release_receipt.py --pytest-junit <junit> --out - --revision abc1234` is run
- **THEN** stdout is valid JSON with `revision == "abc1234"`, `tests.passed == 618`, `tests.failed == 6`, `valid == true`, and the lockfile digest equals `sha256(uv.lock)`

#### Scenario: missing declared asset yields exit 1
- **GIVEN** a manifest override declaring a nonexistent asset
- **WHEN** `scripts/release_receipt.py --check --manifest <override>` is run
- **THEN** exit code is 1 and stderr names the missing path

#### Scenario: receipt contains no secrets
- **GIVEN** a generated receipt
- **WHEN** its serialized content is scanned for `api_key` / `token` / `password` / `secret` patterns
- **THEN** no matches are found

### Requirement: README status claims SHALL be reconciled with the receipt

`README.md` SHALL NOT contain hand-maintained test counts (e.g. "269 tests")
or dependency claims not backed by the manifest (e.g. `cryptography`). It SHALL
document `uv sync --locked` as the install command and point to the release
receipt (CI artifact) as the source of truth for test counts and shipped status.

#### Scenario: README contains no stale test count
- **GIVEN** the repository tree
- **WHEN** README.md is scanned for the string `269`
- **THEN** no match is found in the context of test claims

#### Scenario: README documents the receipt as source of truth
- **GIVEN** the repository tree
- **WHEN** README.md is scanned for `release-receipt` / `release receipt` / `release-check`
- **THEN** at least one match is found

### Requirement: clean-environment CI SHALL validate the release contract

`.github/workflows/release-check.yml` SHALL run on push to `dev`/`master` and
on PRs into both, and SHALL: install with `uv sync --locked`; validate the
manifest + CLI surface (`scripts/release_receipt.py --check`); run the standard
test command; generate the receipt with `--pytest-junit`; and upload it as a
workflow artifact named `release-receipt-<sha>`.

#### Scenario: workflow contains the required steps
- **GIVEN** the repository tree
- **WHEN** `.github/workflows/release-check.yml` is read
- **THEN** it contains `uv sync --locked`, `release_receipt.py --check`, `pytest`, and `upload-artifact`

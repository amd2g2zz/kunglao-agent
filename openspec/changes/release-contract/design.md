# Design — release contract (#80)

## Design Decisions

### D1. Release boundary: repo-owned everything (vendored agents, no external manifest)

The issue offers two options for agent assets: (a) vendor into the repo, or
(b) document a pinned external manifest. Decision: **(a) vendor**.

- README L127 already states the agents "ship with the repo" — the docs promise
  a repo-owned artifact; option (b) would legitimize a contract that is
  host-dependent (`~/.claude/agents/` exists only on the author's machine),
  which is exactly the clean-clone failure the issue reports.
- Reproducibility is the core value of this project (verifiable convergence);
  a release that cannot be reconstructed in another environment is not a release.
- Cost of vendoring: 10 markdown files, ~no size. The `release_receipt.py`
  records their sha256 digests, so drift between the vendored copy and a live
  `~/.claude/agents/` install becomes observable evidence, not silent divergence.

Roster: the 10 agent definitions that exist globally and are referenced by
SKILL.md (L245 pre-installed agents) / README install section:
`kunglao-worker`, `kunglao-redteam`, `ghidra-light`, `floss-filter`,
`pefile-signature`, `cti-correlator`, `go-symbols`, `shodan-host`,
`verdict-scorer`, `verdict-redteam`.

### D2. Dependencies: declared = actually imported (no ad-hoc --with)

Scan of `scripts/ hooks/ tools/ tests/ memory/scripts/` imports yields exactly
four third-party runtime deps: `yaml` (PyYAML), `pefile`, `capstone`,
`jsonschema` (conftest `contract_validator`). `pytest` is the dev extra.
`cryptography`/`requests` are NOT imported anywhere — README's
"cryptography / pyyaml / capstone / pefile / ..." is corrected.

`pyproject.toml` is minimal-but-real: name/version/description,
`requires-python = ">=3.11"`, dependencies above, `[project.optional-dependencies]`
dev = pytest. No `[tool.pytest.ini_options]` — `pytest.ini` already owns that
surface; two configs would split authority for no gain.

`uv.lock` is generated by `uv lock` (uv 0.11.24, universal lockfile) and
committed; `uv sync --locked` becomes the documented install command. The
lockfile sha256 is part of the receipt, so "lock digest" is receipt-verifiable.

Version: `1.9.29` — the version marker already carried by SKILL.md; the
manifest asserts `manifest.version == pyproject.version` (receipt-checked).

### D3. CLI surface: make the documented router real (register verify + record)

`scripts/kunglao.py` docstring (L12-L17) promises `verify` and `record` but the
subparser registry (L60-L79) exposes only `decide` / `tick` / `health`. The
issue's acceptance allows either making the surface real or deleting the docs.
Decision: **add the two subcommands** — the modules already exist
(`kunglao_verify.main(argv)`, `kunglao_record.main(argv)`, both argparse with
optional argv), so wiring is thin delegation. The router surface becomes
`decide` / `tick` / `verify` / `record` / `health`, matching the docstring.

The 8 independent CLIs remain the primary documented interface (README CLI
reference, `tests/test_cli_matrix.py`). `kunglao.py` stays the router; the
phase8-cli-convergence "subcommand → loop-entry" refactor remains deferred —
its acceptance (8 CLIs + router) is what this change makes verifiable.

### D4. Declarative manifest + generated receipt (the two-sided contract)

`release-manifest.yaml` (repo root) is the DECLARED contract — what the release
SHALL contain: schema_version, project, version, requires_python,
dependencies, asset path lists (agents / hooks / templates), CLI inventory,
router subcommands, standard test command. It is hand-maintained ON PURPOSE:
adding a shipped asset without declaring it fails `--check` (fail-open is how
the current contract rotted).

`scripts/release_receipt.py` is the OBSERVED contract — the machine-readable
receipt produced from the current tree:

```json
{
  "schema_version": "1.0",
  "revision": "<git rev-parse HEAD | --revision override>",
  "generated_at": "<ISO8601 UTC>",
  "dependencies": {
    "pyproject": {"path": "pyproject.toml", "sha256": "..."},
    "lockfile":  {"path": "uv.lock", "sha256": "..."}
  },
  "assets": {
    "agents":    [{"path": "agents/kunglao-worker.md", "sha256": "..."}],
    "hooks":     [...],
    "templates": [...],
    "openspec_changes": [{"name": "...", "path": "openspec/changes/<name>", "sha256": "..."}]
  },
  "clis": [{"name": "scripts/kunglao.py", "help_exit": 0}, ...],
  "router": {"command": "scripts/kunglao.py", "subcommands": ["decide", "tick", "verify", "record", "health"], "help_exit": 0},
  "tests": {"command": "python -m pytest -q", "collected": 625, "passed": 618, "failed": 6, "skipped": 1},
  "valid": true
}
```

Validation rules (violation ⇒ `valid: false` + exit 1):
1. Every declared asset exists in the tree.
2. Every declared CLI exists and `--help` exits 0.
3. Every router subcommand parses (`<kunglao.py> <sub> --help` exits 0).
4. `manifest.version` equals `pyproject.toml` version.
5. Receipt emits sha256 digests for all assets (inventory integrity).

Test result: two intake modes —
- `--pytest-junit <file>`: read junit XML (CI passes the pytest step's output;
  no double test run);
- default: run the standard test command (`sys.executable -m pytest -q`) and
  parse the summary line (plus a `--collect-only` probe for `collected`).
- `--no-tests`: omit test result (fast local manifest check).

Exit contract: 0 = receipt written AND manifest/CLI valid (test failures are
DATA, the CI pytest step is the GATE); 1 = receipt could not be produced or
validation failed. `--check` = validate + print, no receipt file.
`--manifest <path>` override exists so tests can exercise failure paths without
copying the repo. `--out -` writes to stdout. Receipt contains NO secrets —
only inventory digests (guard test).

`schemas/release-receipt.json` freezes the shape (repo convention: conftest
`contract_validator`).

### D5. CI: clean-env release-check replaces the boilerplate workflow

`.github/workflows/python-package.yml` is the GitHub template scaffold
(flake8 without config, `if [ -f requirements.txt ]`, targets master only,
never touches uv) — itself part of the broken contract. Replace it with
`release-check.yml`, one job, five steps, no external actions beyond
`actions/checkout@v4` + `actions/setup-python@v5`:

```
checkout → setup-python(3.11) + pip install uv
→ uv sync --locked                      # the documented install command, clean env
→ uv run python scripts/release_receipt.py --check        # manifest + CLI gate
→ uv run python -m pytest -q --junitxml=.pytest-result.xml  # standard test command
→ uv run python scripts/release_receipt.py --pytest-junit .pytest-result.xml --out release-receipt.json
→ upload-artifact release-receipt-${{ github.sha }}
```

Triggers: push to `dev`/`master` + PR into both. Pinning `setup-uv` action
versions is unverifiable offline; `pip install uv` sidesteps that risk.

### D6. README: claims come from the receipt, not hand-typing

- L7 badge → GitHub Actions status badge for `release-check.yml`; the "269
  passed" claim is deleted (it is false at this revision: 618 passed / 6
  known-failing / 1 skipped).
- L101-L132 install: `uv sync --locked` (was `uv sync`), dependency list
  corrected (drop cryptography), agents copy block now backed by real files.
- L260-L269 CLI reference: unchanged (now receipt-validated) + note that
  `kunglao.py` router exposes decide/tick/verify/record/health.
- L283 / L304 / L319-L322 test counts and "shipped" claims → point at the
  release receipt (CI artifact) as source of truth; no hardcoded numbers.
- Add a "Release contract" section: manifest + receipt + CI description, and
  the documented verification sequence a fresh clone runs.

### D7. The 6 pre-existing failures stay untouched

`test_acceptance_overall_passes`, `test_contract_docs::test_skill_lte_500_lines`,
4× `test_convergence_completeness` are owned by parallel #77/#78/#82 work. The
receipt records them as data; CI gates on pytest's exit code; this change never
edits those tests or their targets.

### D8. Secrets hygiene

The receipt inventories paths + sha256 digests only. `.claude/settings.json`
(API keys) and `bins/` remain gitignored/untracked; the no-secrets guard test
scans receipt content for key/token/password patterns.

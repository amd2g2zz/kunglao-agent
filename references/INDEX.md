# references/ Index

Navigation guide for the `references/` directory. Each entry describes what the file contains and when to consult it.

## Top-level references

| File | Purpose | When to read |
|------|---------|--------------|
| `case-book.md` | Documents five real failure modes from prior sessions with their root causes and the v1.9 fixes that address each one. | When you recognize a recurring behavioral pattern (e.g., idling with free slots, re-issuing failed dispatches, stale plans) and want the full story plus fix mapping. |
| `cold-start-contract.md` | Defines the 8-file read sequence for round 0 (cold start) and the incremental-change detection strategy for subsequent rounds, plus Phase 0 setup mandates (wire-up, heartbeat, isolation). | At session start when deciding whether to do a full cold-start read or only re-read changed files, or when configuring Phase 0 hooks and heartbeat activation. |
| `convergence-loop.md` | Describes the 5 convergence-driven behaviors (self-recovery, specialist-first, cost-is-noise, poll-workers, false-completion trap) with case evidence, spin-detection logic, and the failure-analysis gate protocol. | When you need the detailed reasoning behind a convergence behavior, or when diagnosing a spinning/stalled loop or deciding whether a failed attempt warrants a NEGATIVE conclusion. |
| `dynamic-re-tool-priority.md` | Specifies tool-priority order for dynamic RE dispatch (x64dbg > frida > vmr-shell > Qiling), the VM-channel-only mandate, and documented failure modes (x64dbg-automate desync, DHCP drift). | Before dispatching a worker for call-site stepping or dynamic RE to pick the right tool and avoid host-channel violations or syscall-level breakpoint flooding. |
| `excerpt-lint.md` | Defines three mechanical lint rules for condensed decompile excerpts (no unannotated numeric conversion, traceability to raw disasm, no unresolved-variable speculation) and their annotation contracts. | When authoring or reviewing a condensed decompile excerpt fixture, or when running `fixture_excerpt_lint.py` and need to interpret its output. |
| `failure-modes-lifecycle.md` | Catalogs failure modes F1-F6 covering the dispatch/heartbeat/routing lifecycle, plus premature-termination detection (PT1-PT4 fingerprints) with its detector script. | When the user reports dispatch issues (stuck, idle, zombie workers) or premature "done" declarations with open items remaining. |
| `failure-modes-monitoring.md` | Catalogs failure modes F7-F13 covering worker help, self-doubt, state discipline (false PROVEN, cost interruption, hook noise, backtrack failure, repeat work, fan-wen), plus environmental negative-evidence downgrade rules. | When the user reports worker-level problems (false PROVEN, ignored help requests) or when a NEGATIVE conclusion was drawn from a dynamic miss under a self-reported environment fault. |
| `failure-modes-state.md` | Catalogs failure modes F14-F18 covering plan-state consistency (stale blockers, stale claims, no progress indicator, plan-reality drift, integrated state management). | When the user reports plan/status/progress issues such as stale blockers, drifted plans, or missing visual progress indicators. |
| `failure-modes.md` | Index file that splits the 18 failure modes (F1-F18) across three domain files and provides routing guidance for which file to load given a symptom category, plus a summary table of all rows. | When you know a failure-mode occurred but need to quickly identify which domain file (lifecycle/monitoring/state) to load for the full details. |
| `guardrails.md` | The full backing reference for orchestrator guardrails: tool-use boundary, maker-checker, state checkpoint, git requirement, worker monitoring, converge-driven loop, specialist dispatch, and closeout checklist. | When the inline summary in SKILL.md is insufficient and you need the complete rule text, enforcement scripts, or anti-pattern examples for a guardrail. |
| `long-horizon-architecture-2026-07.md` | Pre-implementation research survey of 5 reference architectures (Plan-and-Act, ELHPlan, Task-Decoupled Planning, LangGraph Checkpoint, Anthropic Effective Harnesses) mapped to kunglao-agent failure modes and v1.10 roadmap. | During v1.10 design discussions to cite prior art, or when evaluating whether a proposed architectural change has a reference-paper basis. |
| `malware-phase-routing.md` | Maps file types (PE, ELF, Mono, Office, etc.) to analysis phases (triage, dynamic, specialized static, detection engineering, report) and defines the VM isolation boundary for dynamic analysis. | At the start of a new malware engagement when deciding which analysis phase to enter based on the sample file type. |
| `memory-protocol.md` | Defines a two-tier memory distill pipeline (staging -> longterm) with a 10-item accumulation threshold, atomic clear semantics, entry schemas, and linkage to global Claude memory. | When writing in-session observations to memory/staging/ or triggering a distill to memory/longterm/, or when reasoning about what persists across sessions. |
| `method-constraints.md` | Constraint table for known-incompatible scenarios (Go binary RE, Frida on Go, deep-path host ops, x64dbg breakpoint syntax, VM channel, RVA/VA math) that must be copied into worker dispatch descriptions. | Before dispatching a worker to ensure the correct method constraints are included for the target binary type and tool combination. |
| `operational-mechanics.md` | Provides the HOW behind heartbeat tick loops, worker ping protocols (strike counts, backoff, specialist bootstrap tolerance), self-cap-safe dispatch prose, VM-channel launch sequence, and VM-worker session cleanup. | When implementing or debugging the heartbeat loop, writing dispatch prose, launching x64dbg in the VM, or diagnosing zombie/specialist worker issues. |
| `optimization-2026-08.md` | Background-knowledge compendium holding detailed versions of smart-ping protocol, closeout checklist, worktree source-mount caveats, superseded-path prohibition, and case-book summaries that were moved from SKILL.md to stay under 500 lines. | When you need the full expanded text of a smart-ping protocol, closeout checklist item, worktree caveat, or case-book entry referenced only by pointer in SKILL.md. |
| `schema.md` | Defines all data schemas used by kunglao-agent: boundary_type, fact.status, note.type, claim-register entries, claim_deps.yaml, facts/_INDEX.md conflict/inference conventions, and assignment-class expected-value verification. | When reading or writing structured state files (claim-register.yaml, facts/_INDEX.md, claim_deps.yaml) and need the valid values, conventions, and lint gates. |
| `search-policy.md` | Defines the three-layer search strategy: claim-dependency DAG, computed-priority greedy best-first (with the priority formula), and iterative-deepening tier gate (T1 cheap -> T3 expensive). | Before each dispatch round to run priority.py, check tier gates, and decide which claim to dispatch next in the correct order. |
| `verify-static-vs-dynamic.md` | Distinguishes static vs. dynamic verification strategies: static uses reproduce command plus byte-exact comparison; dynamic uses re-run plus normalized trace diff; non-deterministic tools cap at single-source-dynamic confidence. | When verifying a worker's evidence output to pick the correct verification method (byte-exact vs. normalized trace diff) based on the evidence source. |
| `wal-protocol.md` | Defines the write-ahead log protocol for atomic multi-writer state updates: intent logging in analysis_state.txt, content-addressed fact IDs (SHA-256), and cold-restart reconciliation for in-flight/orphan intents. | When writing fact files and updating claim-register.yaml concurrently, or when performing cold-restart reconciliation after a session crash. |
